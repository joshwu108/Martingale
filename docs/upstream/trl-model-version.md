# Draft comment for TRL rollout version discussion

The [rollout-source RFC #5974](https://github.com/huggingface/trl/issues/5974) defines `model_version` on each `RolloutSample` and on each captured turn, but is closed as not planned. The older [weight-sync interface issue #5195](https://github.com/huggingface/trl/issues/5195) is also closed. Best current venue: [TRL Discussions](https://github.com/huggingface/trl/discussions) under the async GRPO / weight-sync topic, or a current maintainer-selected thread before posting. This draft is ready to paste once a live venue is chosen.

TRL's `model_version` and weight-sync ordering are a useful basis for diagnosing off-policy updates. Would it be feasible to preserve a token-aligned provenance record at the rollout boundary? Minimal fields are `(position, token_id, behavior_logprob_bits, revision_digest)` per generated token. A revision binds the trainer step, parent revision, weights digest, tokenizer digest, and sampler config including dtype and `logprobs_mode`; a later score binds the token position, train revision, and trainer log-prob bits. This allows a sequence to span two versions and lets diagnostics separate lag from the lag-0 engine/trainer floor. The [schema](https://github.com/joshwu108/Martingale/blob/main/docs/design.md) is in section 7; it binds what the engine reports, not whether the token was sampled from that distribution.

In one Qwen2.5-0.5B, TRL 1.13/vLLM 0.28 colocated run, our fp32 trainer disagreed with bf16 vLLM by 0.81 and 1.03 nats on generated tokens at steps 4 and 8. We first called it tail noise, then failed sync. A probe found every one of 494,032,768 vLLM parameters equal to the trainer weight cast to bf16 after each sync. With bf16 autocast the lag-0 floor fell to 0.0001–0.03 nats. The sync was correct; our precision configuration was the cause. [Evidence and scope](https://github.com/joshwu108/Martingale/blob/main/docs/findings/2026-10-06-trl-colocate-sync.md). A startup warning for fp32 trainer forward against a bf16 engine could save others this diagnosis.
