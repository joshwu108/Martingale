# Claude Code Setup Prompt — Project B: `martingale`
## Exact Off-Policy Staleness Accounting for Asynchronous Policy-Gradient RL

Copy everything below this line into Claude Code as your kickoff prompt.

---

You are building **`martingale`**: a correctness-oriented research codebase for the **learner/algorithm side of asynchronous reinforcement learning**. Modern online-RL pipelines (RLHF-style and otherwise) run actors and learners asynchronously: trajectories are generated under behavior-policy revisions that lag the learner's current policy, sometimes with *mixed* revisions inside a single trajectory when weights update mid-rollout. Existing async-RL systems handle staleness with heuristics (bounded lag, importance-weight clipping, stale-sample discarding) and existing serving-infrastructure work stops at recording *which* revision produced *which* token — it explicitly makes no claims about what staleness does to the learning signal. Nobody has built the missing scientific instrument: a system where every action carries an **exact rational behavior probability** bound to an attested revision, where importance weights are **exact**, and where the **true expected gradient** of the estimator — on-policy and stale — is computed by **exhaustive trajectory enumeration in exact arithmetic**, so that staleness bias becomes a machine-checked rational identity or a machine-checked exact inequality rather than a noisy empirical anecdote. You are building that instrument, falsification-first: preregistered kill thresholds, mutation-tested independent checkers, explicit non-claims, and real multi-process asynchrony with crash cuts.

## Research theses (freeze kill rules in `docs/preregistration.md` before implementing any campaign)

**T1 (exact ledger).** In a real multi-process actor/learner pipeline, every trajectory can carry a hash-chained attestation: per action, the behavior revision id (content-addressed digest of the exact policy parameters), the exact rational probability the behavior policy assigned to the chosen action, the draw integer, and the environment transition — such that an independent checker, given only the ledger and the content-addressed revision store, re-derives every probability and draw from scratch and rejects any tampering. Mixed-revision trajectories (revision switch mid-episode) must be first-class: each action pins its own revision.

**T2 (exact unbiasedness identity — the centerpiece).** On finite enumerable MDPs with rational-parameter policies, the following holds as a **machine-checked exact rational equality**, trajectory-enumerated with zero floating point: the per-decision importance-weighted REINFORCE gradient estimator under a stale behavior policy has exact expectation **equal, component by component, as reduced fractions** to the exact on-policy expected gradient. And the corresponding **negative certificate**: PPO's clipped surrogate gradient and a GRPO-style group-relative estimator under the same staleness have exact expectations **not equal** to the true gradient — you must produce the exact rational bias vector, not a float approximation, for committed witness configurations. If the IS identity fails to check exactly, either the implementation or the textbook claim is wrong — finding out which is the work.

**T3 (staleness scaling law, preregistered).** Exact bias of the clipped estimator grows with revision lag. Frozen protocol: MDP family (random rational MDPs, |S| ∈ {3,4,5}, |A| ∈ {2,3}, horizon H ∈ {3,4,5}, 20 MDPs per cell from a fixed campaign seed), policy drift generated by running exact gradient ascent steps of rational learning rate so revision r+k is a deterministic exact function of r, lags k ∈ {0,1,2,4,8}, clip ε ∈ {1/10, 2/10, 3/10}. Measure exact squared-L2 bias (a rational — no square roots) relative to exact squared gradient norm. **Kill rule:** the monotone-growth thesis is dead in a cell if exact relative squared bias at k=8 is not strictly greater than at k=1 for a majority of that cell's MDPs; the global thesis is dead if it dies in a majority of cells. Also preregister the descriptive question of *where clipping helps*: cells where the clipped estimator's exact bias is *smaller* than the unclipped-but-variance-blind estimator's exact error profile must be reported, not buried.

**T4 (float divergence).** Production-style float importance-weight paths (log-prob subtraction in float32, exp, ratio clipping) produce **decision-relevant divergences** from exact arithmetic: cases where the float ratio falls on the opposite side of the clip boundary than the exact ratio, flipping which branch of the clipped objective is active and therefore changing the gradient direction contribution of that sample. Frozen search: 10^5 candidate (exact-ratio, parameterization) pairs per cell constructed to land within float32-ulp-scale distance of the clip boundaries at ε ∈ {1/10, 2/10}, plus long-trajectory cumulative-product ratios (per-decision products over H ∈ {16, 64, 256} steps) where float underflow/overflow and exact values disagree about clip activation. **Kill rule:** dead if zero boundary flips are found in the entire budget. (Boundary flips are near-certain to exist; the scientific content is their *frequency and magnitude structure*, which nobody has mapped.)

**T5 (async protocol safety).** The pipeline's revision-pinning protocol — actors pin a revision for each action, the learner publishes revisions, the ledger must never attribute an action to a revision that was not the actor's pinned revision at draw time — holds under real process interleavings and crash cuts, and a finite-state TLA+ model of the protocol passes its invariants while a deliberately weakened variant (remove the pin-before-draw ordering) yields a checked-in counterexample trace.

## Hard constraints

- Python 3.10+ **CPU only**. `uv` with committed lockfile. PyTorch is permitted *only* inside `campaigns/float_baselines.py` as one of the float defendants; the core system is pure Python + `fractions`/integers.
- **Policy parameterization decision (M1, requires my sign-off):** softmax over float parameters yields irrational probabilities, which would poison exact enumeration. Present three options with trade-offs: (a) direct rational simplex parameterization (policy is a table of rationals summing exactly to 1; gradient ascent projected exactly — cleanest for T2/T3, and gradients w.r.t. simplex parameters are exact rationals); (b) softmax computed in float64 once per revision, then exactly integerized, with the integerized table *declared* to be the policy (float enters at one declared boundary; exact everywhere downstream; but then "gradient" must be defined w.r.t. the declared table); (c) polynomial-parameterized policies with rational coefficients where probabilities and their parameter-gradients are exactly rational by construction. I expect (a) as the default for T2/T3 with (b) as the bridge used only in T4's float-divergence study. Wait for my choice.
- Exact arithmetic rules identical in spirit to serious exact-systems work: floats convert exactly at declared boundaries only; inf/nan rejected loudly; no float comparisons on any decision or measurement path in T2/T3; all reported biases are exact rationals serialized as reduced numerator/denominator strings.
- Randomness: keyed BLAKE2b + rejection sampling for all action draws, keyed by `(seed, actor_id, episode, step)`. Exposed seed; explicitly not a security boundary (state in `docs/nonclaims.md`).
- Real asynchrony: actors and learner are separate OS processes communicating over `multiprocessing` queues (explicit `spawn` start method — the macOS default, and it flushes hidden global-state bugs), with a deterministic-scheduling test harness (a controller that releases queue operations in a scripted order) so interleaving bugs are reproducible. Crash cuts use real `SIGKILL`. Any ledger persistence that must survive a `SIGKILL` uses full-durability sync: `fcntl(fd, F_FULLFSYNC)` on Darwin (plain `fsync` on macOS does not guarantee durable storage), `os.fsync` elsewhere, on files and parent directories, with atomic rename as the commit point.
- Independent checkers in `checker/`, importing nothing from `src/` (CI-enforced), written to reject.
- Enumeration must be feasibility-checked: total trajectory count (|A|^H per start state, times |S| starts) must stay under 10^7 per configuration; the campaign runner must compute and assert this bound before running, and refuse otherwise.
- Every file under ~400 lines. `make check` runs everything.
